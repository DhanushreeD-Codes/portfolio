Job Application Tracker & Resume Intelligence Platform

A production-style .NET backend platform that helps job seekers manage applications, interviews, resumes, contacts, notes, and follow-ups in one place.

C# .NET 10 ASP.NET Core EF Core SQL Server Clean Architecture xUnit

Business Problem

Job seekers often manage their applications across spreadsheets, email folders, browser bookmarks, and notes. This makes it difficult to track application status, prepare for interviews, remember follow-ups, and understand which applications are producing results.

This platform centralizes the job-search workflow and provides a clear record of every application, interview, contact, and follow-up.

Core Features

User Management

User registration, login, profile management, and secure access to personal job-search data.

Application Tracking

Track job applications through statuses such as Saved, Applied, Interview, Offer, and Rejected.

Resume Management

Upload and manage resume versions, associate resumes with applications, and maintain application history.

Interview Tracking

Record interview rounds, schedules, feedback, interviewers, and outcomes.

Notes & Follow-Ups

Add notes to applications and schedule follow-up reminders so important actions are not missed.

Search & Analytics

Search and filter applications, then view insights such as response rate and interview conversion rate.

Planned Architecture

The solution will follow Clean Architecture to keep business logic independent from frameworks, databases, and external services.

Domain Layer

Contains core business entities, value objects, enums, and domain rules.

Application Layer

Contains application services, use cases, interfaces, validation logic, and business workflows.

Infrastructure Layer

Contains EF Core, database context, repositories where appropriate, file storage, and external service implementations.

API Layer

Contains ASP.NET Core controllers or minimal API endpoints, request/response models, authentication, and API documentation.

Engineering Decisions

Why Clean Architecture?

Clean Architecture helps keep the core job-application domain independent from ASP.NET Core, EF Core, and SQL Server. This improves testability and makes future changes easier to manage.

Why EF Core?

EF Core provides productive data access, strong LINQ support, migrations, and change tracking. It is suitable for this application because most operations are standard relational data operations.

Why a Status Workflow?

Application status is a business workflow, not just a string field. Defining valid transitions helps prevent inconsistent data and makes the domain easier to understand.

Planned API Areas

  • Authentication and user profile APIs
  • Job application CRUD and status-transition APIs
  • Resume upload and management APIs
  • Interview tracking APIs
  • Notes and follow-up APIs
  • Search, filtering, pagination, and analytics APIs

Testing Strategy

The project will include automated tests to verify both business rules and API behavior.

  • Unit tests for domain rules and application services
  • Integration tests for API endpoints and database operations
  • Validation tests for invalid requests and business-rule violations
  • Authentication and authorization tests

Current Status

The project is currently in the design phase. The next steps are to finalize the domain model, define the database schema, create the solution structure, and implement the first API endpoints.
